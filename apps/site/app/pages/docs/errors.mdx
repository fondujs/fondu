## The error page

An unknown URL, a `throw new HTTPException(403)` or an error in a handler: a page request gets `app/pages/error.tsx`
with the status, inside the layout, with the shared props. API clients get plain text, or the `HTTPException`'s own
response.

```tsx
// app/pages/error.tsx
export default function ErrorPage({ status }: { status: number }) {
  return <h1>{status === 404 ? 'Page not found' : 'Something went wrong'}</h1>
}
```

Another page: `createApp({ errorPage: 'errors/show' })`. None, plain text for everyone: `errorPage: false`. Without
`app/pages/error.tsx`, the same plain text.

## In development

A 500 is a report of the error instead: the message, and the stack with your files first. During a visit, Inertia
shows it in its dialog. And `render()` of a page that doesn't exist says which file to create.

An error before any handler runs, in a route that throws as it is imported, is Vite's: its overlay shows it, as a
whole page, and the next edit reloads the page.

## Answers from outside the app

During a visit, an answer that isn't an Inertia page, such as a proxy's 502 or a CDN's 524 timeout page, is shown in
Inertia's dialog, in production too. Fondu itself answers visits in production with pages only, errors included, so
those come from what stands in front of the app. Inertia's `httpException` event (`router.on('httpException', …)`)
lets the app handle them otherwise.

## Your own handling

`createApp()` returns a Hono app: its `notFound()` and `onError()` replace Fondu's.

```ts
const app = createApp()

app.onError((error, c) => {
  report(error)
  return c.text('Something went wrong', 500)
})

export default app
```
