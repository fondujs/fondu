Fondu is a small meta-framework for full-stack React apps, built on [Hono](https://hono.dev),
[Vite](https://vite.dev) and [Inertia](https://inertiajs.com). It runs on Bun, Cloudflare Workers and Node.

## Routes and pages

An app has two kinds of files. **Routes** in `app/routes/` are Hono handlers that run on the server; the file path is
the URL. **Pages** in `app/pages/` are React components. A route renders a page by name, with its props:

```ts
// app/routes/users/[id].ts: GET /users/7
export const loader = defineHandler.withValidator({ params })(async (c, { params }) =>
  render(c, 'users/show', { user: await getUser(params.id) }),
)
```

```tsx
// app/pages/users/show.tsx: the component's props are the page's props
export default function Show({ user }: { user: User }) {
  return <h1>{user.name}</h1>
}
```

The first request gets the page rendered on the server. From then on, Inertia takes over in the browser: a link or a
form makes a request to the same route, which answers with the next page's name and props as JSON, and React swaps the
page without a full reload. There is no API to write for your pages and no client-side router to keep in sync with the
server: the routes are the only router.

## Who does what

Fondu writes only what none of them does: Inertia's server side for Hono, which no official adapter covers, and what
holds the parts together.

| Part                                                                                                                                         | Done by                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Visits, history, prefetching, forms, `<Head>`, deferred and merged props, infinite scroll                                                    | `@inertiajs/react`                                              |
| HTTP, middleware, CSRF protection, security headers                                                                                          | Hono and its middleware                                         |
| Dev server and production build                                                                                                              | Vite, with `@hono/vite-dev-server` or `@cloudflare/vite-plugin` |
| Finding the page component, the entry of the server render                                                                                   | `@inertiajs/vite`                                               |
| Inertia's server side (the protocol, forms' errors and flash data), `routes/`, typed pages and URLs, the document, error pages, static pages | Fondu                                                           |

So most of what you write is Hono's API on the server and Inertia's in the browser, and their docs apply as they are.
The pages here cover what Fondu adds.

## Fondu and @hono/inertia

[@hono/inertia](https://github.com/honojs/middleware/tree/main/packages/inertia) is Hono's middleware for Inertia:
your Hono routes answer with Inertia's pages, and the rest is yours to set up: the document, the client entry, how
pages are found and built, React, Vue or Svelte. It is the way to add Inertia pages to a Hono app you already have.

Fondu is a framework on the same parts, for a new React app. Besides the protocol, which it implements with what forms
and private pages need (validation errors and flash data, once props, history encryption), it makes the decisions an
app around it needs:

- routes and pages as files, with layouts;
- the server render, in the same process on every target;
- forms: invalid input back to the page with its errors, flash data, Precognition;
- the document, with a Content Security Policy;
- types between them: `render()` checked against the page, `href()` against the routes;
- static pages, and an app to start from.
