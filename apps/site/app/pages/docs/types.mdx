## Generated types

The dev server and the build write `app/fondu.gen.d.ts`: every page with its component, every route with its URL.
From it:

- `render(c, name, props)` takes only pages that exist, with the props their component takes.
- `href(path, params)` takes only URLs of `app/routes/`, with their params.

Commit the file and leave it be: it changes when you add, move or delete a page or a route.

## Typed URLs

`href()` from `fondu/client` builds a URL of a route. A typo in the path, a missing param or a param that isn't one is
a type error:

```tsx
import { Link } from '@inertiajs/react'
import { href } from 'fondu/client'

<Link href={href('/users/:id', { id: user.id })}>{user.name}</Link>

// one of a route's actions: POST /users/7?rename
<Form action={href('/users/:id?rename', { id: user.id })} method="post">…</Form>
```

The method is Inertia's to say: `<Link href={href('/logout')} method="post" as="button">Sign out</Link>`.

## Shared props, flash data and context values

Types for what a middleware sets go where it is set, as declarations of Hono's and Inertia's own types:

```ts
// app/routes/_middleware.ts
declare module 'hono' {
  interface ContextVariableMap {
    user: User | null // c.set('user', …), c.get('user')
  }
}
declare module '@inertiajs/core' {
  interface InertiaConfig {
    sharedPageProps: { auth: { user: { name: string } | null } } // share(), usePage().props
    flashDataType: { message?: string } // flash(), usePage().flash
  }
}
```

`share()` and `flash()` then take only those, `usePage()` returns them, and a page prop named like a shared prop but of
another type is a type error (it would hide the shared one).

## Pages that don't type their props

A page whose component takes no props is rendered without them: `render(c, 'about')`. One that takes any object
(`Record<string, unknown>`) takes any props.
