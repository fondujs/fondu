Fondu can write pages as static files at build time: static site generation (SSG). They are served without rendering
them again, and Inertia's visits keep working. On Bun, Cloudflare Workers and Node; this site is built that way.

```ts
// vite.config.ts
fondu({ target: 'node', prerender: true }) // or 'bun', 'cloudflare'
```

## Choosing the pages

A route opts in with `export const prerender`; a `_middleware.ts` sets it for its directory and below. The nearest
setting wins:

```ts
// app/routes/(marketing)/_middleware.ts: every page below
export const prerender = true

// app/routes/(marketing)/contact.ts: not this one
export const prerender = false

// app/routes/blog/[slug].ts: a dynamic route lists its pages' params
export const prerender = () => posts.map((post) => ({ slug: post.slug }))
```

`app/routes/_middleware.ts` with `export const prerender = true` makes every page static.

## How it works

The build starts the server it built (`node` or `bun dist/server/index.js`, or the Worker in wrangler), asks it for the pages
to prerender, and writes each twice in the client build:

- as a document, `docs/intro.html`, for a first visit;
- as its page object, `_fondu/pages/docs/intro.json`, for Inertia's visits: Fondu's client reads it instead of asking
  the Worker.

Then:

- On Cloudflare, Workers Static Assets serve the files without running the Worker.
- On Bun and Node, the server answers a static page from its file before the routes, with the app's security headers.

The server still answers every other URL, a page that isn't static or one that doesn't exist. In development, it
answers all of them.

On Cloudflare, the Worker the build starts runs locally, as in development: `.dev.vars` overrides the `vars` of
`wrangler.jsonc`. A static page is written with those values and deployed as it is, so a value meant for your
machine, a `localhost` site URL say, ends up in production. Keep what static pages show out of `.dev.vars`.

## What a static page can be

A static page is the same for everyone. It is rendered once, for a visitor with no cookies and no query string, shared
props included. So the build stops, naming the route, when a page:

- answers with a status other than 200, such as a redirect;
- takes POSTs at its URL (an `action`): Cloudflare answers those with 405 for a static file, so Fondu refuses them
  on every target;
- uses deferred props or infinite scroll, which need the Worker.

## Headers

On Bun and Node, a static page gets the headers of any page of the app, the Content Security Policy with a fresh nonce
included, and its scripts that had the build's nonce get this one.

On Cloudflare, the pages' security headers are written to `_headers`, which Workers Static Assets apply to static
files. The policy drops its nonce there, as a file served to everyone can't have one: the scripts that had it are
allowed by their hashes instead, so an inline script of [the document](/docs/document) runs on a static page too.

## A new deploy

Each page records the build it belongs to. After a deploy, a visit from a tab opened before it reloads the page, as
Inertia does for a new version of the assets.
