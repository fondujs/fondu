Fondu checks the seams between the server and the browser at compile time: what a route sends to a page, the URLs
your pages link to, the input your handlers read. Rename a prop, move a route or change a schema, and TypeScript points
at every place that no longer fits, before anything runs.

## Where the types come from

There is nothing to declare twice. Each type has one source, and the rest follows from it:

| Source                                | Checks                                                                |
| ------------------------------------- | --------------------------------------------------------------------- |
| a page component's props              | `render(c, Page, props)`: every prop is there and fits                |
| the files in `app/routes/`            | `href('/users/:id', { id })`: the URL exists, its params, its actions |
| a route's query schema                | `href('/search', { query })`: the query the route takes               |
| a handler's schemas (`withValidator`) | the `body`, `query` and `params` the handler receives                 |
| declarations next to your middleware  | `share()`, `flash()`, `usePage()`, `c.get()`                          |

The dev server and the build write the routes' types into `app/fondu.gen.d.ts` as your files change; commit it.

## Page props

The component is the source: its parameter's type is what `render()` takes for that page.

```tsx
// app/routes/users/[id].tsx
export const loader = defineHandler(async (c) => {
  const user = await getUser(c.req.param('id'))
  return render(c, Show, { user }) // error: canEdit is missing
})

export default function Show({ user, canEdit }: { user: User; canEdit: boolean }) { … }
```

## URLs

`href()` from `fondu/client` takes the URL patterns of `app/routes/`, and a route's actions as `?name`:

```tsx
href('/users/:id', { id: 7 }) // '/users/7'
href('/users/:id?rename', { id: 7 }) // '/users/7?rename': actions.rename
href('/users/:id') // error: the param is missing
href('/user/:id', { id: 7 }) // error: no such route
```

`query` and `hash` add a query string and a fragment. When the route checks its query with `withValidator({ query })`
(its loader, a `.ts` file's `GET`, or the action), `query` is typed by that schema; otherwise it takes any values.

```tsx
// app/routes/search.tsx
const query = z.object({ q: z.string(), page: z.optional(z.coerce.number()) })
export const loader = defineHandler.withValidator({ query })(async (c, { query }) => …)

// anywhere
href('/search', { query: { q: 'ada', page: 2 }, hash: 'results' }) // '/search?q=ada&page=2#results'
href('/search') // error: the schema requires q
href('/users/:id', { id: 7, query: { tab: 'posts' } }) // '/users/7?tab=posts': no schema, any query
```

A param can't be named `query` or `hash`: they are `href()`'s. A value that is `undefined` or `null` is left out, and
`z.coerce.number()` takes any value (a string or a number), as the URL carries it as text.

A redirect takes `href()` too: `return c.redirect(href('/users/:id', { id: user.id }), 303)`.

## Handler input

`defineHandler.withValidator()` types the handler's input from its schemas, as they parse it: with
`z.coerce.number()`, `params.id` is a `number`.

```ts
const params = z.object({ id: z.coerce.number() })

export const loader = defineHandler.withValidator({ params })(async (c, { params }) => {
  params.id // number
})
```

Any [Standard Schema](https://standardschema.dev) library works: [Forms and validation](/docs/forms).

## Shared props, flash data and context values

What a middleware sets is typed where it is set, by declaring Hono's and Fondu's own interfaces:

```ts
// app/routes/_middleware.ts
declare module 'hono' {
  interface ContextVariableMap {
    user: User | null // c.set('user', …), c.get('user')
  }
}
declare module 'fondu' {
  interface Register {
    shared: { auth: { user: { name: string } | null } } // share(), usePage().props
    flash: { message?: string } // flash(), usePage().flash
  }
}
```

`share()` and `flash()` then take only those, and `usePage()` returns them. A page prop named like a shared prop but
of another type is an error, as it would hide the shared one from the layout.

## What crosses as JSON

Props travel to the browser as JSON, so a page's prop types are what it receives: a `Date` arrives as a string, a
`Map` or a `Set` as `{}`, and `undefined` fields are left out. `render()` checks both sides of that:

```tsx
// app/routes/posts/[slug].tsx
export default function Show({ post }: { post: { title: string; publishedAt: string } }) { … }
```

```ts
render(c, Show, { post: { title, publishedAt: new Date() } }) // fine: JSON makes the Date a string
```

A page that types a prop as `Date`, `Map`, `Set` or a function is an error at `render()`, as the page would get
something else. Anything with a `toJSON()` passes for what that returns.

## Setup

None beyond `tsconfig.json`: a new app has it. Keep `app/fondu.gen.d.ts` committed, so a fresh clone or CI has the
types before the first build.
