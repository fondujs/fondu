A page is a React component: the default export of a route file. `app/routes/users/[id].tsx` is the page at
`/users/:id`, and its loader, in the same file, renders it with its props.

```tsx
// app/routes/users/[id].tsx
import { defineHandler, render } from 'fondu'

// GET /users/7, on the server
export const loader = defineHandler(async (c) => {
  const user = await getUser(c.req.param('id'))
  return render(c, Show, { user: { name: user.name } })
})

// the page: the part of the file the browser gets
export default function Show({ user }: { user: { name: string } }) {
  return (
    <>
      <title>{`${user.name} · My app`}</title>
      <h1>{user.name}</h1>
    </>
  )
}
```

A page can also be an [MDX](/docs/mdx) file. The parts around pages are [layouts](/docs/layouts). How the app moves
from one page to the next is in [Navigation](/docs/navigation).

## Props

The props are what the loader gives `render()`. They are the page's only data from the server.

```ts
render(c, Show, { user })
render(c, Show, { user }, { status: 201 }) // another status
```

- `render()` is type-checked against the component: a missing prop, or one of the wrong type, is an error.
- The props travel as JSON. A `Date` arrives as a string, so the page types it `string`. A `Map`, a `Set` or a
  function can't be sent: typing a prop that way is an error. [Type safety](/docs/type-safety) has the details.
- The props are written into the page's HTML and JSON: anyone who can see the page can read them. Send what the page
  shows (`{ name: user.name }`), not whole records.
- A route file renders its own page only. To use another route's page, make it this file's default export too:
  `export { default } from './index.tsx'`.

A page without a loader is rendered on GET with no props of its own.

## Title and meta tags

A page renders its own `<title>`, `<meta>` and `<link>` tags where it likes; React moves them into `<head>`, on the
server too. A title is one string, hence the template literal above.

```tsx
<>
  <title>{`${post.title} · Blog`}</title>
  <meta name="description" content={post.summary} />
  <link rel="canonical" href={`https://example.com/posts/${post.slug}`} />
</>
```

What every page shares (the charset, icons, fonts) goes in [the document](/docs/document).

## Shared props

Props every page gets, such as the signed-in user, are set once in a middleware with `share()`:

```ts
// app/routes/_middleware.ts
import { defineMiddleware, share } from 'fondu'

export default defineMiddleware(async (c, next) => {
  const user = await currentUser(c)
  share(c, { auth: { user: user && { name: user.name } } })
  await next()
})
```

A shared value can be a function: it runs only when a page renders, not for API requests. Pages and layouts read
shared props with `usePage().props`. [Type safety](/docs/type-safety) shows how to type them.

## Reading the page in a component

`usePage()` from `fondu/client` returns the page on the screen, in any component:

| Field   | Is                                                               |
| ------- | ---------------------------------------------------------------- |
| `props` | the page's props, with the shared props and `errors`             |
| `url`   | the page's URL (path and query)                                  |
| `flash` | the data an action left for this page with `flash()`, shown once |

```tsx
import { usePage } from 'fondu/client'

export function Greeting() {
  const { props } = usePage()
  return props.auth.user ? <p>Hello, {props.auth.user.name}</p> : null
}
```
