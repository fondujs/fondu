## Pages

A page is a React component, the default export of its route file: `app/routes/users/[id].tsx` is the page at
`/users/:id`. The component's props are the page's props:

```tsx
// app/routes/users/[id].tsx
export default function Show({ user }: { user: User }) {
  return (
    <>
      <title>{`${user.name} · My app`}</title>
      <h1>{user.name}</h1>
    </>
  )
}
```

A page renders its own `<title>`, `<meta>` and `<link>` where it likes: React puts them in `<head>`, on the server too.
A title is one string, hence the template literal. A page can also be [MDX](/docs/mdx); [layouts](/docs/layouts) are
`_layout.tsx` files in the directories of `app/routes/`.

## `render()`

The loader renders its file's page, with its props:

```ts
render(c, Show, { user })
render(c, Show, { user }, { status: 201 })
```

It takes the props the component takes: a missing prop or one of the wrong type is a type error. The props arrive as
JSON: a `Date` for a `string` prop is fine, a `Map` is a type error. It renders the page of its own route file only;
another route's page is its own too once it is that file's default export:
`export { default } from './index.tsx'`.

## Links and forms

Links are `<a href>`, forms `<form method="post">`, with URLs from [`href()`](/docs/type-safety). In the browser:

- A link fetches the next page; the layouts stay mounted, with their state. The page starts at the top, or at its
  `#fragment`.
- A form's answer at the same URL (back with errors, `back(c)`) replaces the page where it is, the scroll position kept;
  with errors, the page keeps its state too, what was typed included. Elsewhere, it's a new page in the history.
- Back and Forward fetch the page again, as a link does, and scroll it where it was left.
- Screen readers hear the new page's title.
- An answer that isn't a page (a file, a proxy's error, a redirect to another site) is shown as the browser would
  show it.
- A navigation that takes a while shows a progress bar at the top of the page: `fondu({ progress: { color, delay,
forms } })` in `vite.config.ts` sets its color (the page's text color by default), how long a navigation runs before
  it shows (350 ms), and whether forms' submissions show it too (`forms: false` when their buttons do);
  `progress: false` leaves it out, for your own with `useNavigating()`.

From `fondu/client`:

|                      |                                                                                 |
| -------------------- | ------------------------------------------------------------------------------- |
| `usePage()`          | the page on screen: `props` (shared ones and `errors` included), `url`, `flash` |
| `useNavigating()`    | `true` from a click or a submit until the next page is on the screen            |
| `reload()`           | the page's props again, its state and scroll position kept                      |
| `loadDocument(href)` | a document load: for what a page can't change in place (`<html lang>`)          |

In code, `location.assign(url)` navigates as a link would.

## Shared props

Props every page gets, such as the signed-in user, are shared from a middleware with `share()`:

```ts
// app/routes/_middleware.ts
import { defineMiddleware, share } from 'fondu'

export default defineMiddleware(async (c, next) => {
  const user = await currentUser(c)
  share(c, { auth: { user: user && { name: user.name } } })
  await next()
})
```

A value can be a function: it runs when a page renders, not for the other requests. The page reads them with
`usePage().props`. [Type safety](/docs/type-safety) shows how to type them.

## After an action

- `back(c)`: a redirect to the page the request came from.
- `flash(c, { message: 'Saved' })`: data for the next page only, in `usePage().flash`.
- `c.redirect(url, 303)`: to another page, a file or another site; the browser shows what is there.
