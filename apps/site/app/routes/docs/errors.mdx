## The error page

An unknown URL, a `throw new HTTPException(403)` or an error in a handler: a page request gets `app/routes/_error.tsx`
with the status, inside the root layout, with the shared props. API clients get plain text, or the `HTTPException`'s
own response.

```tsx
// app/routes/_error.tsx
export default function ErrorPage({ status }: { status: number }) {
  return <h1>{status === 404 ? 'Page not found' : 'Something went wrong'}</h1>
}
```

Without `app/routes/_error.tsx`, plain text for everyone.

## In development

A 500 is a report of the error instead: the message, and the stack with your files first; a navigation loads it as a
document. Fix the code and save: the report reloads.

An error before any handler runs, in a route that throws as it is imported, is Vite's: its overlay shows it, as a
whole page, and the next edit reloads the page.

## Answers from outside the app

An answer that isn't a page, such as a proxy's 502 or a CDN's timeout page, comes from what stands in front of the
app: Fondu answers navigations with pages, errors included. The browser shows it as it would without JavaScript: a
link's loads the URL as a document, a form's replaces the page.

## Your own handling

`createApp()` returns a Hono app: its `notFound()` and `onError()` replace Fondu's.

```ts
const app = createApp()

app.onError((error, c) => {
  report(error)
  return c.text('Something went wrong', 500)
})

export default app
```
