# i18n

Docs: [i18n](https://fondu.dev/docs/i18n.md).

Fondu has no translations of its own. A page's URL says its language, with an optional segment, and a library has the
messages. The docs use Paraglide JS (typed message functions, no provider); i18next works too.

## URLs

The base language has no prefix, the others have one:

| File                          | URLs                               |
| ----------------------------- | ---------------------------------- |
| `routes/[[locale]]/index.tsx` | `/`, `/de`, `/fr`                  |
| `routes/[[locale]]/about.tsx` | `/about`, `/de/about`, `/fr/about` |
| `routes/admin/index.tsx`      | `/admin`: the base language only   |

`params` lists the prefixes, so `/xx/about` and `/en/about` are 404s:

```ts
// app/routes/[[locale]]/_middleware.ts
import { baseLocale, locales } from '#/paraglide/runtime.js'

export const params = { locale: locales.filter((locale) => locale !== baseLocale) }
```

## Paraglide

- `npx @inlang/paraglide-js@latest init --outdir ./app/paraglide` sets it up; tsconfig needs `allowJs`.
- In `vite.config.ts`: `paraglideVitePlugin({ project, outdir, strategy: ['url', 'baseLocale'], trailingSlash:
  'never' })`. URLs have no trailing slash in Fondu: `/de/` redirects to `/de`.
- `routes/_middleware.ts` wraps the request in `paraglideMiddleware`, so messages and `getLocale()` know the language
  on the server (and on the 404 page). Give it a `Request` whose URL has `c.req.path` (decoded) and no body.
- The language lives in AsyncLocalStorage: Node, Bun, and Cloudflare Workers with Node.js compatibility (on from
  compatibility date 2026-08-04, before it `nodejs_compat`).
- The compiled messages aren't committed: run `paraglide-js compile` before `tsc` in the typecheck script.

## Messages

`messages/de.json` holds `{ "greeting": "Hallo, {name}!" }`. `m.greeting({ name })` is the same function in a page and
on the server.

- A validation message is a function, called as the body is checked: `z.minLength(1, { error: () => m.name_required()
  })`. One called as the module loads would be in the base language.
- Where no request says the language (a scheduled task, a later email), pass it: `m.welcome({ name }, { locale })`.

## Links

Wrap `href()` once, typed as `href()`, and use it for links, form actions and redirects:

```ts
// app/lib/i18n.ts
import { href } from 'fondu/client'

import { localizeHref } from '#/paraglide/runtime.js'

export const localizedHref: typeof href = (path, ...params) => localizeHref(href(path, ...params))
```

`back(c)` returns to the page's own URL, so it keeps the language.

## Switching and the document

Another language is another document. Remember it with `setLocale(locale, { reload: false })`, then
`loadDocument(localizeHref(href('/about'), { locale }))` (a plain navigation would keep the document's `lang`).
`app/document.tsx` has `<html lang={getLocale()}>`.

## Search engines

Each page lists its URL in every language, itself included, as full URLs:
`<link rel="alternate" hrefLang={lang} href={href} />`, with `x-default` for the base language. Build them in the
loader from `localizeHref(path, { locale })` and `c.req.url`.

For static pages, `export const prerender = () => params.locale.map((locale) => ({ locale }))` next to `params` writes
each language; the base language's comes with them.

## The home page in the visitor's language

The URL decides, so `/` is the base language. To redirect `/` by the cookie or `Accept-Language`, do it in
`routes/_middleware.ts` before Paraglide's, for GET `/` only, with `strategy: ['url', 'cookie', 'baseLocale']`:

- check the language against the app's own (`toLocale`, `extractLocaleFromHeader`) before using it;
- set `Vary: Accept-Language, Cookie`, on the home page's own response too;
- don't prerender the home page: a static file is served before any middleware.

## i18next

Messages are looked up by key at runtime, through a provider, with no AsyncLocalStorage:

- the language: `c.req.param('locale') ?? 'en'` in `routes/[[locale]]/_middleware.ts`, with the same `params`;
- on the server: an instance per request, `i18next.cloneInstance({ lng })`;
- the messages: `share(c, { locale, messages: () => resources[locale] })`;
- in the browser: `routes/_layout.tsx` makes an instance once per language (`i18next.createInstance()`, `init({ lng,
  resources, initAsync: false, interpolation: { escapeValue: false } })`) and wraps the page in `<I18nextProvider>`.
